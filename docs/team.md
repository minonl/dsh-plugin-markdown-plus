# 团队工作方式（Agent Team Protocol）

> 目的：**避免单个 agent 自说自话**。每个变更必须经过「需求 → 实现 → 验证 → 评审 → 用户验收」，
> 每一环都留下可核对证据；涉及交互/范围/取舍的决策，**只能由用户拍板**，agent 只提供选项与证据。

## 角色

| 角色 | 职责 | 产出 |
|---|---|---|
| **Product Owner（用户本人）** | 唯一验收权；决定范围、交互、是否发布 | 验收结论（通过 / 打回 + 原因） |
| **PM / 调度（主 agent）** | 拆解任务、派活、收口；不替用户做产品决策 | todo、任务分派、PR 汇总 |
| **UX/产品分析** | 交互方案对比（截图 + 利弊表），**给选项不给结论** | `artifacts/ux/<时间戳>/` 截图 + 选项矩阵 |
| **实现（Implementer）** | 按已确认方案写代码，小步提交 | 代码 + 单测 |
| **QA / 验收** | 独立验证：单测、dev e2e、真实 DSH e2e、作用域/回归检查 | `artifacts/qa/<时间戳>/report.json` + 截图 |
| **Reviewer** | 只看代码与契约：边界、幂等、泄漏、a11y、与官方契约一致性 | findings 列表（阻断 / 建议） |
| **Release** | tag → CI → npm/GitHub Release；发布后健康检查 | 发布记录 + registry 证据 |

## 硬规则

1. **一个变更一个 PR**；PR 描述必须包含三块：**验收标准 / 证据 / Reviewer 结论**。
2. **没有证据不算完成**：UI 类必须有真实环境截图；行为类必须有 e2e 断言；修复类必须能复现原故障（反向验证）。
3. **禁止 agent 自决产品交互**：至少给 2 个选项 + 真实截图，由用户选。
4. **作用域纪律**：插件只在目标容器内生效（例：大纲只允许出现在 `[data-sidebar-right-tab]` 预览容器），
   验证时必须包含「不该出现的地方没有出现」。
5. **失败要如实**：e2e/测试失败就 red，不允许为了绿而放宽断言。
6. **不碰别人的工作**：不 stash/不提交他人未提交改动；不全局 pkill。

## 并行分工（同一轮内不重叠）

同一轮里多个 agent 并行时，必须满足：**读写文件不重叠**、**端口/进程不冲突**、**各自产物目录独立**。

- QA 只读代码 + 跑测试（用独立端口）
- UX 只读 DOM + 注入样式做对比（不改源码）
- Reviewer 只读代码
- Implementer 独占 `src/`、`test/` 写权限

## 交付节奏

```
PM 拆解 → (UX 选项 | Reviewer 基线审查) → 用户拍板 → Implementer → QA 证据 → Reviewer 结论 → 用户验收 → Release
```
